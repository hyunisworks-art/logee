## 実行方法

```bash
cd 30_dev/36_tool/logic-tree/tests
npm install                 # 初回のみ
npx playwright test         # ローカル（static-server.js が自動起動）
```

| 環境変数 | 用途 |
| --- | --- |
| `PW_BASE_URL` | 本番URLに対して流す（例: `https://logee-logic-tree.vercel.app`）。指定時はローカルサーバーを起動しない |
| `PW_CHANNEL` | `chrome` で実機Chromeを使う。MODの無限ループ検証はこれが必要（後述） |

`index.html` は Quill を CDN（jsdelivr）から読み込むため、テスト実行にはネットワーク接続が要る。

### カバレッジ計測

```bash
COVERAGE=1 npx playwright test && node coverage-report.js
```

V8のJSカバレッジをテストごとに `.coverage/` へ採取し、`coverage-report.js` が `index.html` のインラインスクリプト分だけを集計する（Quillとサンドボックスiframeは除外）。行番号は `index.html` の行番号に揃えて出力する。

V8のレンジは「親と食い違う部分だけ」を報告するため、テスト間の統合はレンジのcount合算ではなく**バイト単位に展開してからORを取る**。合算するとあるテストで通らなかった分岐が未実行と誤判定される（初版でこの誤りがあり、実際は通っている `deleteTree` の分岐を未実行と表示していた）。

## テスト方針

- アプリの状態は `localStorage` にあるため、各テストは必ず消去済みの状態から始める（`helpers.js` の `openApp`）。
  ただし消去は初回ロード時だけに限定する。リロードで消してしまうと「保存されている」ことを検証できない
- パネル操作は「選択中しかボタンが出ない」ため、必ず `selectNode()` を挟む
- 「＋下位」「＋同列」で追加したパネルはその場で編集状態になる。ダブルクリックは不要で `typeInEditing()` を使う
- 構造の検証は画面ではなく `localStorage`（`logicTree.v2`）を読んで比較する。描画方式（入れ子DOM／絶対配置）に依存させないため

## 修正記録：修飾キー付きショートカットを割り当てられなかった不具合（2026-08-14）

分岐テストの追加中に判明。設定画面のキー割り当ては `keydown` のたびに `normalizeKey()` の結果で確定していたが、`Ctrl+Shift+K` のような組み合わせは **Ctrl の keydown が先に届く**。`normalizeKey()` は修飾キー単体でも `"Ctrl"` という空でない文字列を返すため、その時点で確定してしまい、修飾キー付きのショートカットが一切割り当てられなかった（`Ctrl` だけが登録される）。

修正: `normalizeKey()` は `Control` / `Shift` / `Alt` / `Meta` 単体の keydown に対して空文字を返すようにした（呼び出し側の `if (!sc) return;` がそのまま効く）。テストは `branches.spec.js` の「修飾キー付きのキーを割り当てられる（Ctrl単体では確定しない）」。

## 調査記録：無限ループMODの1秒タイムアウト（#10）

`security-check-mod-2026-08-08.md` は「計算はiframe内なのでメインスレッドは止まらない／1秒で解除、UIは操作可能なまま」と記録している。今回2つの環境で実測したところ、**結果がブラウザによって割れた**。

| 環境 | 結果 |
| --- | --- |
| 実機 Chrome（`PW_CHANNEL=chrome`） | 記録どおり。約1秒で解除ダイアログが出て、UIは操作可能なまま |
| Playwright 同梱 Chromium 1.62 | **タブが固まったまま復帰しない**。45秒待っても解除されず、`page.evaluate` も応答しない |

この差は、ブラウザが `sandbox` 属性付き iframe を親と別プロセスへ隔離するかどうかによる。隔離されない場合、MODの `while(true)` は親と同じスレッドを占有するため、解除用の `setTimeout(..., 1000)` 自体が発火できない。

つまり1秒タイムアウトは**ブラウザのプロセス隔離に依存した保護**で、隔離しない環境ではフリーズを防げない。実機Chromeでは有効に働くため、アプリ側は現状のままとし、この前提を `security-check-mod-2026-08-08.md` の制限事項に追記した。テスト#10は隔離するブラウザでしか検証できないので `PW_CHANNEL` 指定時のみ実行する。
